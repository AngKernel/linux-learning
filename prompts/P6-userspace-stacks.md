背景：我是 C/C++ 开发，熟悉 VPP/DPDK 框架，正在读 Linux 6.18 网络子系统，以后准备从零实现一个用户态 TCP 协议栈。现阶段的目标是理解：成熟的用户态协议栈各自做了哪些设计取舍，背后的原则是什么。这是纯理解型任务，不写任何协议栈代码。

阅读对象（每个都先固定一个 tag 或 commit，写进笔记开头；所有结论以该版本源码为准，函数名和结构体先 grep 确认，不能凭记忆，确认不了的标"未确认"）：
1. lwIP：结构最小、最好读，作为基准
2. VPP host stack（src/vnet/tcp 和 session 层）：我熟悉 VPP 框架，重点看 TCP 如何嵌入 graph node 模型
3. Seastar native stack：C++，按核分片、无锁设计的代表
4. F-Stack（简要即可）：把 FreeBSD 协议栈移植到 DPDK 上，作为"直接搬运内核栈"这条路线的对照

源码获取：把以上项目克隆到 linux-learning 仓库之外的目录（例如 ../third_party/），不要把第三方源码提交进仓库。

输出：notes/04-userspace-stacks/，每个协议栈一个文件，最后加一份横向对比。

每个协议栈都按以下维度分析（每条都给出 文件路径:行号）：
1. 整体架构图（Mermaid）：从网卡或 DPDK 收包到应用拿到数据的完整路径，和 Linux 内核路径的对应关系
2. 包缓冲区：用什么结构（pbuf / vlib_buffer / mbuf 等），零拷贝做到哪一步，和 sk_buff 的对比
3. 连接查找：流表的数据结构、哈希方式、多核下怎么分布
4. 定时器：重传、delayed ACK、TIME_WAIT 是怎么实现的（时间轮还是其他结构），时间来源是什么
5. 线程模型：单线程、按核分片还是共享加锁；连接如何固定到核；RSS 怎么配合
6. TCP 实现完整度：拥塞控制算法、SACK、窗口缩放、时间戳、TSO/LRO 等，各自是否支持
7. 给应用的 API：BSD socket 兼容、回调还是 future，各有什么代价
8. 相比内核简化或省略了什么，以及为什么可以省
9. 测试方式：它们自己怎么测协议栈

横向对比（comparison.md）：
- 一张对比表，覆盖以上所有维度
- 设计哲学：每个协议栈的核心假设是什么（例如"一个核只服务自己的连接""应用愿意为性能改写代码""只跑在专用机器上"），这些假设如何决定了它的每一个设计
- 和 Linux 内核的逐项对照：在缓冲区、并发、定时器、批处理、API 这几个维度上，内核为了"通用"做了什么，用户态栈为了"专用"放弃了什么，换来了什么
- 共性规律：几个用户态栈不约而同做出的选择，以及它们之间分歧最大的地方和分歧的原因
- 推荐阅读顺序：如果我只有 10 小时，先读哪几个文件

完成后汇报：每个协议栈最核心的设计洞见、最大的局限，以及它们共同揭示的"内核网络栈的瓶颈到底在哪里"。
