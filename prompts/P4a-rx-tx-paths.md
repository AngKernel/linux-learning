章节安排：
第 1 章 收包主线：数据包从到达网卡到用户态程序拿到数据
  按下面的阶段推进，每个阶段都从源码确认真实的函数和调用链：
  网卡 DMA 写入 RX ring（缓冲区由谁分配、page_pool 的作用）→ 硬中断 → NAPI 调度与 NET_RX_SOFTIRQ → 软中断处理与 NAPI poll 预算 → 驱动 poll 函数里的 XDP 挂载点 → 构建 skb → GRO → 协议无关的接收核心（抓包 tap、tc ingress、按协议分发）→ IP 层接收、netfilter 挂载点、路由决策与 early demux → 本地投递 → TCP 接收入口、socket 查找 → 已建立连接的快速路径、数据进入接收队列 → 唤醒等待进程（包括 epoll 的唤醒链）→ 用户调用 recv 后，数据从 skb 拷贝到用户态缓冲区
  支线（简要说明，标注入口函数即可）：RSS/RPS/RFS 多核分发；包在哪些地方会被丢弃，以及怎么看 drop reason

第 2 章 发包主线
  send() → TCP 发送 → 分段与发送窗口控制 → IP 输出 → 邻居子系统 → qdisc → 驱动发送 → TX 完成中断与资源回收

每章统一格式：
1. 一张总览图（Mermaid 时序图或流程图）
2. 调用链：每一步写 函数名 + 文件路径:行号 + 一句话说明它做了什么
3. 关键数据结构，只列和本章相关的字段
4. "为什么这样设计"：至少 3 条，结合性能、并发、可扩展性
5. 验证实验：在 QEMU 虚拟机里可以运行的 bpftrace、ftrace function_graph 或 perf 命令，用来亲眼看到这条路径，并附上预期输出的样子
6. 3–5 道自测题，答案放在文末折叠块里
7. 对用户态协议栈的启示（2–3 条）
