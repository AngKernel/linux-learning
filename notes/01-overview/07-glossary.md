## 要点回顾

- 对象名、队列名、执行上下文和协议术语分别回答不同问题。
- skb、socket、sock 不是同义词。
- 窗口、预算、队列长度的单位应到具体实现确认。
- 同名“连接”可能指应用 TCP 状态，也可能指防火墙观察状态。
- 术语表用于定位，状态转换和边界条件仍需看后续章节。

## 自测题

1. conntrack 中有一个流，是否代表本机一定有对应 TCP 应用 socket？
2. rwnd、cwnd 和 pacing 分别约束什么？
3. socket backlog、监听队列、硬件 RX ring 能否当成同一个队列？
4. GRO、GSO、TSO 的处理方向和执行位置有何不同？

<details>
<summary>答案</summary>

1. 不一定，纯转发流量也可以被连接跟踪。
2. 分别对应接收端能力、发送端拥塞控制的在途限制、发送的时间节奏。
3. 不能；分别涉及 socket 并发延后处理、连接建立、驱动与硬件交接。
4. GRO 聚合接收数据，GSO 提供延后分段的数据表示/软件分段体系，TSO 由网卡承担 TCP 分段。

</details>

## 与 DPDK/VPP 的对照

RSS、DMA、描述符和多队列是熟悉的共同词汇。遇到 skb、NAPI、socket backlog、RCU 时应重新核对 Linux 的对象与执行规则，不能直接把 mbuf、PMD 循环或工作线程的所有权模型套进去。
